# SSR A 层规则创建与测试工作流

> 来自 2026-07-23 实战：FANTASY×6 + ZY×1 共 7 个生图 Skill 接入 SSR

## 核心原则：粗中有细

- **粗**：正则要宽到覆盖口语化表达（"电影那种感觉""照片修好看""中国风的"）
- **细**：每条规则最多推 2-3 个 skill，禁止一次推 5+ 个

## 五步流程

### 1. 列出目标 skill 和触发场景

对每个 skill，列出用户可能用的表达方式（正式术语 + 口语变体）：

```
skill: zy-cinematic-realism
触发: 关键帧 / keyframe / 电影单帧 / 电影感 / 电影画面 / 电影那种感觉 / cinematic

skill: fantasy-life-force-portrait  
触发: 角色设计 / 角色板 / 人像 / 肖像 / 照片升级 / 照片修好看 / 普通照片

skill: cinema-dna-21x9x3
触发: 分镜构图 / 构图分析 / 视线流量 / 电影构图 / 画面分析
```

### 2. 写初始正则——宁窄勿宽

从最精确的关键词开始，避免一开始就写 `.*` 泛匹配：

```python
# ✅ 好：从具体开始
r'(关键帧|keyframe|电影单帧|cinematic.*still)'

# ❌ 差：一上来就全匹配
r'(电影|视频|画面)'  # 会命中一切
```

### 3. 模拟测试——用 execute_code 跑真实查询

```python
tests = [
    "帮我生成一个电影感的画面",      # 应该命中
    "东方美学风格的设计",            # 应该命中  
    "今天天气怎么样",                # 不应命中
]
for test in tests:
    for pattern, rule_data in rules.items():
        if re.search(pattern, test, re.IGNORECASE):
            ...
```

必须同时测正向（应命中）和负向（不应命中）。

### 4. 找缺口——口语变体最容易漏

常见漏法：
- "电影那种感觉" → 规则写了"电影感"但不匹配"电影.*感觉"
- "中国风" → 规则写了"东方美学"但不匹配"中国风""国风"
- "照片修好看" → 规则写了"人像摄影"但不匹配"照片.*修"
- "分镜" 单独出现 → 规则写了"分镜.*构图"但不匹配纯"分镜"

**每次测试至少跑 8-10 个口语化变体。**

### 5. 扩宽 + 复测——循环到全绿

扩宽策略：给核心关键词加 `.*` 可选后缀，或加同义词管道：

```
v1: r'(分镜.*构图|构图.*分析)'        → "分镜" 单独不漏
v2: r'(分镜|分镜.*构图|构图.*分析)'   → ✅

v1: r'(东方.*海报)'                   → "中国风的设计" 不漏  
v2: r'(东方|中国风|国风|中式)'        → ✅
```

但不要扩过头——`.*` 要配合至少一个限定词。

## 最终质量门

每条规则通过以下检查才算合格：

- [ ] 正式术语能命中（"电影单帧"）
- [ ] 口语变体能命中（"电影那种感觉"）
- [ ] 不会误命中无关话题（"天气"不触发）
- [ ] 每条规则推 ≤3 个 skill
- [ ] 已通过 execute_code 跑至少 10 个测试用例
- [ ] 备份文件存在（a_rules.json.bak.xxx）

## 教训

本会话踩的坑：
1. **删旧规则忘了补宽** — 删掉含"电影感"的旧规则后，新规则没包含"电影感"，导致回归。改规则前先 grep 确认旧规则覆盖了哪些关键词。
2. **口语比专业术语多得多** — 用户极少说"关键帧 prompt"，更多说"电影那种感觉"。写规则时至少想 3 种口语变体。
3. **单条泛规则推全库=噪音** — 最初"海报"一条规则推 3 个 skill。改为"海报"兜底推 1 个 + "东方海报""城市海报"各推 1 个细分。
4. **备份每次都要** — 改 a_rules.json 前必须 cp 备份。本次会话留了 5 个备份点（v1→v5）。
