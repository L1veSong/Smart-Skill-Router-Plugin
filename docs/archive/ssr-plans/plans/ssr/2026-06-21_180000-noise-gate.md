# SSR B 层升级 + A 层扩展方案 v3

> **Goal:** 噪音归零，信号 ≥90%

> **Architecture:** 
> ```
> 消息 → A 层（免费/0延迟）→ 命中 → Embedding 补充
>                         → 未命中 → B 层（DeepSeek, ¥0.0002/2s）
>                                      → NO  → 静默
>                                      → YES → B 层直接匹配 skill
> ```

> **Why this works:** 
> - A 层：精确中文短语，零误报（已验证），快速覆盖 40% 场景
> - B 层：LLM 语义理解，兜底 A 层盲区。一次 API 调用完成门控+匹配
> - 两层互补，都不漏才叫真漏——概率远低于单层

## Task 2: B 层升级 — 加门控判断

**Risk:** 低。改动在 `_match_b_main()` 内部，调用方不变。

**File:** `~/.hermes/plugins/ssr/__init__.py`

**Step 1: 修改 B 层 prompt**

```python
# 旧 prompt（纯匹配）
"你是技能匹配器。可用技能：\n{skill_list}"

# 新 prompt（先判断再匹配）
"先判断用户消息是否需要工具。不需要→回答NO。需要→回答YES并列出最多3个最匹配的技能名。可用技能：\n{skill_list}"
```

**Step 2: 修改 `_match_b_main()` 返回解析**

```python
# 旧：直接解析 JSON
def _match_b_main(user_message):
    ...
    content = data["choices"][0]["message"]["content"]
    return _parse_b_response(content)

# 新：先检查 NO
def _match_b_main(user_message):
    ...
    content = data["choices"][0]["message"]["content"]
    if content.strip().upper().startswith("NO"):
        return None  # B 层判断不需要 skill
    return _parse_b_response(content)
```

**Step 3: 调 max_tokens=200**（reasoning 需要 ~100 tokens）

**验证:** B 层对噪音返回 None，对信号返回 skill 列表。

## Task 3: Embedding 静默

**Risk:** 低。逻辑修改在主调用流程。

**File:** `~/.hermes/plugins/ssr/__init__.py`

**Step 1: 找到主调用函数**

```bash
grep -n 'def _recommend\|_match_a_layer\|_match_embedding\|_match_b_main' ~/.hermes/plugins/ssr/__init__.py
```

**Step 2: 修改调用流**

A 层不命中 → 走 B 层。B 层说 NO → 全局静默。

```python
result = _match_a_layer(msg)
if not result:
    result = _match_b_main(msg)  # B 层门控+匹配
    if not result:
        return None              # 静默
# Embedding 补充（只有确认需要 skill 时才激活）
emb = _match_embedding(msg)
return merge(result, emb)
```
