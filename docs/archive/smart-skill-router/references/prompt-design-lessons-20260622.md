### 坑点 59: prompt"闲聊→NO"导致LLM过度保守——意图≠能力（2026-06-22 两轮实测）

**症状：** 纯LLM方案(p2)两轮测试均54%。"帮我写论文""帮debug代码""帮部署到Vercel"→NO_NEED。第二轮优化prompt后不变。

**根因：** prompt写"闲聊/感叹/问候→不需要skill"。LLM把"帮我写论文"理解成"我可以直接帮，不需要额外skill"——混淆了"我能做"和"不该推skill"。

**修复：** prompt改为"纯闲聊/问候/寒暄→不需要。任何有任务意图的消息→需要"。embedding候选上下文是关键——不是帮LLM省token，是给LLM一个锚定范围，让它的判断从"218选N"变成"这8个里哪个对"。

**教训：** LLM的意图判断=上下文相关。给它218个skill它分心，给它8个embedding候选它精准。embedding的角色是"缩小LR的搜索空间"，不是"帮LLM省token"。
